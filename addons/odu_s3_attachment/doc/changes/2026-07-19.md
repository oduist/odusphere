# 2026-07-19

Hardened S3 backend lifecycle, transactional cleanup, concurrent migration,
image transformation, and garbage collection after code review.

## tech_spec.md

### Changed

- **Constraints & Invariants** — backend code and bucket are now immutable while
  live or GC-queued objects exist; such a backend cannot be deleted and must be
  archived instead.
- **Write path** — every prospective upload is registered in the separately
  committed GC spool before S3 is touched, so a later database rollback leaves
  a recoverable cleanup intent.
- **Serving path** — Image field names with derived dimensions (for example
  `avatar_128`) are treated as transforms and stream through Odoo for resizing.
- **Migration** — attachment rows are locked against concurrent replacement or
  deletion; storage swaps are conditional; each record uses a savepoint; any
  failure keeps migration active for a later retry.
- **Garbage collection** — the autovacuum gate includes archived backends.

```diff
- Backend code was the only protected location value; deletion remained allowed.
+ Backend code and bucket are protected, and owning backends cannot be deleted.
- Migration used an unconditional SQL swap and batch-wide rollback handling.
+ Migration serializes rows, swaps conditionally, and isolates failures per record.
- GC ran only while an active backend existed.
+ GC also processes objects belonging to archived backends.
```
