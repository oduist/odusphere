# 2026-07-02

New module **`odu_s3_attachment`**: offloads user-attached `ir.attachment`
binaries to one or more S3-compatible object stores and serves them via
presigned URLs, while Odoo keeps serving its own web assets. Adapted from the
VelesAgro `s3_attachment` (Odoo 15, single backend) to OduSphere / Odoo 19 with
**multiple backends** and the v19 storage/serving APIs.

## tech_spec.md

### Added

- **Identity & Manifest** — `odu_s3_attachment` `19.0.1.0.0`, `depends
  ["odu_base", "web"]`, external lib `boto3`.
- **Models & Fields** —
  - `odu.s3.backend` (Model): per-store connection + routing record
    (`name`, `code` unique/slug, `active`, `sequence`, `endpoint_url`,
    `public_endpoint_url`, `bucket`, `region`, `access_key`, `secret_key`,
    `mimetype_prefixes`, computed `status`).
  - `odu.s3.gc` (Model): deferred-deletion queue (`store_fname` unique/indexed).
  - `odu.s3.settings` (TransientModel): global routing + migration console,
    backed by `ir.config_parameter` (no `res.config.settings`/`base_setup`).
  - `ir.attachment` (`_inherit`): routing/storage/serving/migration/GC, no new
    stored fields.
- **Business Rules & State** — keep-local filter, priority+MIME backend
  selection, marker format `s3://<code>/<sha[:2]>/<sha>`, the v19 write-path
  bridge (checksum→backend pending map on the cursor), presigned-URL 302
  serving via `_to_http_stream`, storage-level migration, dedup-aware
  multi-backend GC.
- **Methods & Actions**, **Security**, **Views & UI**, **Automation** — full
  inventory; cron `ir_cron_odu_s3_migrate` (30 min, inactive) and the
  `_gc_odu_s3_store` autovacuum.

```diff
+ ## Models & Fields
+ odu.s3.backend (multi-backend connection+routing), odu.s3.gc (GC queue),
+ odu.s3.settings (global settings), ir.attachment (_inherit: storage/serving).
+ ## API Endpoints
+ No new controllers; direct download = 302 via ir.attachment._to_http_stream
+ on the core /web/content and /web/image routes.
```

## admin_guide.md

### Added

- New **Admin Guide**: registering backends and how priority+MIME routing
  spreads content across different S3 stores; global routing & direct-download
  settings; the background migration console (batch size, time window,
  start/stop); deduplication, deferred deletion, and fallback notes; a minimal
  AWS IAM policy; troubleshooting.

## user_guide.md

### Added

- New **User Guide**: the feature is transparent for end users (attach/open/
  download unchanged); explains that downloads may redirect to a temporary,
  personal cloud link and to re-download rather than reuse an old link.
