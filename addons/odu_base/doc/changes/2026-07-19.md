# 2026-07-19 — odu_base

Security hardening of the public contact endpoint and the install policy
(security code audit follow-up).

## tech_spec.md

### Added
- **Models & Fields:** `odu.contact.message.client_ip` (Char, readonly, indexed) —
  source IP captured at submission, used for the per-IP rate limit.
- **Business Rules & State:** new section *Public Contact Endpoint — Abuse Controls*
  documenting the body-size cap (413), honeypot, and per-IP rate limit (429) with the
  two tuning system parameters.
- **Methods & Actions:** `button_immediate_install` override; controller helpers
  `_contact_rate_limited` and `_int_param`.

### Changed
- **Identity & Manifest:** version `19.0.1.0.0` → `19.0.1.1.0`.
- **Business Rules & State:** the install policy is now asserted in **both**
  `button_install` and `button_immediate_install`; the "out of scope" note now spells out
  that the policy is a UI/RPC-button guard, not a hard boundary against a server admin.
- **API Endpoints (`POST /api/contact`):** request flow now includes the pre-parse
  body-size check (413), the per-IP rate limit (429), and recording `client_ip`.

```diff
 ## Models & Fields
   odu.contact.message:
     name / email / message / handled
+    client_ip (Char, readonly, index) — source IP for rate limiting
```

```diff
 POST /api/contact behavior:
+  413 Request too large  (Content-Length > 64 KB, before parse)
   honeypot -> 200, store nothing
   validate name/email/message
+  429 Too many requests  (>= max per IP within window minutes)
-  create odu.contact.message (name, email, message)
+  create odu.contact.message (name, email, message, client_ip)
```

## admin_guide.md

### Changed
- **Contact Requests inbox:** the inbox/form now shows the source IP; the spam-guard
  paragraph replaces "no rate limiting" with the three built-in controls (honeypot,
  size cap, per-IP rate limit).

### Added
- **Contact-form rate limit:** new section documenting the two tuning parameters
  (`odu_base.contact_rate_limit_max` / `…_window_minutes`, defaults 10/10, `0` disables)
  and the requirement to run Odoo in `proxy_mode` behind the gateway for accurate per-IP
  keying.
