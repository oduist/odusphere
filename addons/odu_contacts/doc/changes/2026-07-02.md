# 2026-07-02

New module `odu_contacts`: a top-level **Contacts** workspace (partner directory +
website contact requests with a triage workflow, chatter and activities), superseding
the administrator-only Contact Requests inbox in `odu_base`.

## tech_spec.md

### Added

- Full initial SPEC for `odu_contacts`.
- **Identity & Manifest** — `depends = ["odu_base", "mail"]`, `application = True`,
  category `Contacts`; data load order security → data → request views → partner
  views → menus.
- **Models & Fields** — extends `odu.contact.message` via
  `_inherit = ["odu.contact.message", "mail.thread", "mail.activity.mixin"]`; adds
  `state` (Selection new/in_progress/done, default `new`, required, indexed, tracked)
  and `user_id` (Many2one `res.users`, "Assigned To", indexed, tracked).
- **Business Rules & State** — three-state triage; one-directional `handled` bridge
  (`handled = state == "done"`); on-install deactivation of
  `odu_base.menu_odu_contact_messages`; capture stays in `odu_base`'s public endpoint.
- **Methods & Actions** — `create`/`write` overrides + `_odu_sync_handled` helper.
- **Security** — `base.group_user` full CRUD on `odu.contact.message` and
  `res.partner`.
- **Views & UI** — list / kanban (`default_group_by="state"`) / form (statusbar +
  `<chatter/>`) / search for requests; a reuse-only `res.partner` action; the
  top-level **Contacts** menu with **Contacts** and **Requests** sub-items.
