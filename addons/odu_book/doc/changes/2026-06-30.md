# 2026-06-30

## admin_guide.md

### Added

- New section **"Upstream updates — protected core modules"** at the top of the
  Admin Guide, documenting that `odu_base` and `odu_book` are upstream-owned and
  must not be edited in a sphere (the sphere↔template update overwrites them via
  the `merge=theirs` lane). Directs admins to extend behavior with their own
  `odu_*` module instead.

```diff
+ ## Upstream updates — protected core modules
+
+ `odu_base` and `odu_book` are part of the shared OduSphere template ...
+ Do not edit anything inside `addons/odu_base/` or `addons/odu_book/` ...
+ To change or extend core behavior, create your own `odu_*` module ...
```

> Note: this entry documents only the Admin Guide content change. The merge model
> itself (`.gitattributes` lanes, `scripts/`) is repository infrastructure, not
> part of the odu_book module SPEC, so `tech_spec.md` is unchanged.

### Changed

- In the **"Upstream updates — protected core modules"** section, the example
  list of sphere-owned files the update preserves no longer cites
  `config/odoo.conf` (removed together with the local `docker compose` stack —
  the sphere is now provisioned exclusively by the OduSphere CLI). Replaced it
  with `LANG.md`, another sphere-owned config file.

```diff
- the update keeps this sphere's `website/`, its own `odu_*` modules, `README.md`,
- `config/odoo.conf` and the sphere system map `.docs/architecture.local.md`.)
+ the update keeps this sphere's `website/`, its own `odu_*` modules, `README.md`,
+ `LANG.md` and the sphere system map `.docs/architecture.local.md`.)
```
