# Changes archive added to the Book

A new **Changes** menu was added next to the documentation. It crawls every
`odu_*` module's `doc/changes/*.md` files and renders them as a day-by-day
archive, like a blog timeline. This is the very first entry of that archive.

## user_guide.md

### Added
- "How to read the change archive" section explaining the new **Changes** menu.
- A note at the top describing the two menus of the Book app
  (**Documentation** and **Changes**).

## tech_spec.md

### Added
- Method `get_changes(self)` and helper `_read_module_changes(self, module_name)`.
- JSON endpoint `POST /odu_book/changes`.
- Client action `action_odu_book_changes` and menu `menu_odu_book_changes`.
- OWL client action `ChangesApp` (template `odu_book.ChangesApp`).
- Markdown renderer: `diff` fenced blocks now colour `+`/`-` lines via
  `.o_diff_add` / `.o_diff_del`.
- Constants `CHANGES_DIRNAME` and `CHANGE_FILE_RE`.

### Changed
- The menu tree was reorganised — the root **Book** menu is now a container
  with two children instead of opening the documentation directly:

```diff
- menu_odu_book_root  -> action_odu_book          (root menu opened the docs)
+ menu_odu_book_root  (container, no action)
+   menu_odu_book_doc      -> action_odu_book          (Documentation)
+   menu_odu_book_changes  -> action_odu_book_changes  (Changes)
```

# Admin Guide (Adminbook) added

Human documentation is now split into two audiences: the **User Guide**
(Userbook, for everyone) and the new **Admin Guide** (Adminbook, for Settings
administrators only — module settings and privileged tasks). The Admin Guide is
restricted both in the menu and on the server.

## admin_guide.md

### Added
- New file `doc/admin_guide.md` for `odu_book` itself — documents the three
  Book sections, who can see each, and how Admin Guide access is enforced.

## user_guide.md

### Changed
- The intro now lists **three** menus (User Guide / Admin Guide / Changes)
  instead of two; the "what is true now" line now names **User Guide**.
- "How to extend the Book" now mentions `doc/admin_guide.md`.

```diff
- The **Book** app has two menus:
- - **Documentation** -- the current state of every module's guide.
- - **Changes** -- a day-by-day archive of what was changed in the documentation.
+ The **Book** app has three menus:
+ - **User Guide** -- the current state of every module's guide, for everyday users.
+ - **Admin Guide** -- settings and tasks for administrators (Settings admins only).
+ - **Changes** -- a day-by-day archive of what was changed in the documentation.
```

## tech_spec.md

### Added
- Method `get_admin_book(self)` (admin-gated via `base.group_system`,
  raises `AccessError`) and shared helper `_collect_pages(self, filename)`.
- JSON endpoint `POST /odu_book/admin`.
- Client action `action_odu_book_admin` and menu `menu_odu_book_admin`
  (`groups="base.group_system"`).
- OWL client action `AdminBookApp` — subclass of `BookApp` overriding
  `static endpoint = "/odu_book/admin"`.
- Constants `ADMIN_GUIDE_FILENAME` and `ADMIN_GROUP`.

### Changed
- `_read_module_guide(module_name)` was generalised to
  `_read_module_doc(module_name, filename)`; `get_book` now delegates to the
  shared `_collect_pages`.
- `BookApp` reads its source from a static `endpoint` property instead of a
  hard-coded `/odu_book/book`, so the Adminbook can reuse it.
- Menus renamed: **Documentation** → **User Guide**; added **Admin Guide**.

```diff
  menu_odu_book_root  (container, no action)
-   menu_odu_book_doc      -> action_odu_book          (Documentation)
-   menu_odu_book_changes  -> action_odu_book_changes  (Changes)
+   menu_odu_book_doc      -> action_odu_book          (User Guide)
+   menu_odu_book_admin    -> action_odu_book_admin    (Admin Guide, base.group_system)
+   menu_odu_book_changes  -> action_odu_book_changes  (Changes)
```

# Multilingual documentation — read-path (Phase 1)

The Book is now multilingual-ready. The User Guide and Admin Guide are served in
each reader's Odoo language, preferring a translated mirror under
`doc/i18n/<lang>/` and falling back to the source file. The system still ships
**English only** (`LANG.md` source `en`, no targets yet) — the mechanism and the
tooling are in place to add a language later.

## admin_guide.md

### Added
- "Documentation languages" section — how the Book picks a reader's language,
  pre-generated (not live) translations, and the `odu-doc-i18n` skill.

## tech_spec.md

### Added
- Helper `_doc_lang(self)` (short language code from context/user).
- Multilingual read-path: `doc/i18n/<lang>/<file>` preferred, source fallback;
  leading i18n provenance marker stripped before render.
- Constants `I18N_DIRNAME` and `I18N_MARKER_RE`.

### Changed
- `get_book` / `get_admin_book` now resolve `_doc_lang()` and serve translated
  guides; `_collect_pages` and `_read_module_doc` gained a `lang` argument.

```diff
- _read_module_doc(module, filename)                      # source file only
+ _read_module_doc(module, filename, lang)                # i18n/<lang>/ then source
+   doc/i18n/<lang>/<filename>   (preferred)
+   doc/<filename>               (source fallback)
```

> The **Changes** archive is intentionally *not* translated (`changes/` is
> `source-only` in `LANG.md`).
